# أثر — ATHAR STUDIO

React 19 + Vite 7 + Firebase 11 (Node 20.19+) — مطابق لملف «بيانات منصة أثر».

    npm install
    npm run dev      # تطوير محلي
    npm run build    # الناتج في dist
    npm run preview

## الصفحات
`/` الموقع · `/#admin` لوحة الإدارة · `/#studio` استديو القوالب · `/#creative` صانع الهوية والتوقيع والبصمة · `/#account` حسابي · `/#terms` و`/#privacy` الوثائق القانونية · `/studio/index.html` نسخة الاستديو المباشرة

## ما يُكمل من لوحات الحسابات
1. Firebase Authentication: فعّل Google وأضف نطاق Vercel إلى Authorized domains.
2. Firestore: انشر `firestore.rules` كاملاً.

4. أرسل طلباً تجريبياً، ثم ادخل `/#admin` وتأكد من ظهوره.

## الدخول والتصفح (تسجيل كسول + رابط سحري)
- **التصفح والمعاينة مجانيان للجميع** بلا تسجيل: الموقع، الخدمات، المتجر، القوالب، وصانع الهوية.
- **نقطة التحول:** أول ضغطة على استخدام فعلي («اطلب الحزمة»، «تصدير PNG»، «حفظ التصميم»، «تنزيل SVG/PNG»، «اطلب الخدمة») تفتح نافذة الدخول وتحفظ الخدمة المقصودة في `sessionStorage`، ثم يُعاد الزائر إليها تلقائياً بعد الدخول.
- **الدخول برابط سحري:** يُرسل Firebase رابط «تأكيد الدخول» إلى البريد، مع زر «إعادة إرسال» وتنبيه لفحص مجلد الرسائل غير المرغوبة. Google متاح كبديل.
- **الموافقة إلزامية:** خياران منفصلان (شروط الاستخدام + سياسة الخصوصية) مع روابط تفتح النص كاملاً. زر «تسجيل الدخول» يبقى معطّلاً بلون باهت حتى يصح البريد ويُحدَّد الخياران معاً.
- عند إتمام الدخول يُكتب سجل موافقة في `consents/{uid}`: البريد، التاريخ، `termsVersion` و`privacyVersion`، ونوع المتصفح. الإصدارات في `src/atharConfig.js`، والنصوص في `src/legalText.js`.

### تشغيل الدخول بالبريد (خطوة من لوحة Firebase)
1. Firebase Console ← Authentication ← Sign-in method ← فعّل **Email/Password** ثم **Email link (passwordless sign-in)**.
2. Settings ← Authorized domains: أضف نطاق الإنتاج (مثل `athar-website.vercel.app`) و`localhost` (مضاف افتراضياً).
3. القوالب: عدّل قالب رسالة «Email address verification» بالعربية إن رغبت. الرابط يفتح الموقع مباشرة ويعيد المستخدم لنفس الصفحة.

## المتجر الرقمي وحساب العميل
- الحزم الأربع وأسعارها في `src/bundles.js` (بدون عيّنات مجانية).
- الزر في المتجر ← `/#account`: تسجيل دخول Google ← تأكيد الطلب ← يُنشأ `orders/{uid_bundleId}` بحالة `pending`.
- لا توجد بوابة دفع مربوطة: تؤكد الدفع يدوياً من `/#admin` ← «الطلبات والإيصالات» (الحالة «مكتمل — الملفات متاحة»)، فتظهر ملفات الحزمة في حساب العميل.
- روابط الملفات: `/#admin` ← «التسليم». قواعد `firestore.rules` تمنع قراءتها إلا لمن أُكّد دفعه.
- للتسليم الفوري الفعلي لاحقاً: اربط Moyasar/Tap مع Cloud Function تغيّر الحالة إلى `paid` تلقائياً.
- مهم: انشر `firestore.rules` المحدّثة (فيها orders وdeliveries) وإلا لن يعمل الشراء.

## الدفع بالتحويل (urPay) والإيصال → Google Drive
1. العميل: `/#account` ← يظهر له الآيبان واسم المستفيد (من `src/payment.js`) ← يحوّل المبلغ ← يرفع صورة/PDF الإيصال.
2. الإيصال يُرفع مباشرة إلى Google Drive الخاص بأثر (`atharstudio653@gmail.com`) داخل مجلد `Athar / Customer Receipts`، عبر جسر Google Apps Script (`public/apps-script/Code.gs`). اسم الملف يبدأ برقم الطلب، وتُرسل رسالة تنبيه إلى بريد الأستوديو.
3. يُحفظ الطلب `orders/{uid_bundleId}` بحالة `pending_review` مع `receiptDriveId` و`receiptDriveUrl` (لا يُحفظ الإيصال نفسه في Firestore).
4. أنت: `/#admin` ← «الطلبات والإيصالات»: تعاين الإيصال، تضغط «تنزيل على الجهاز» لتحميله على هاتفك، تطابق الحوالة ثم تغيّر الحالة إلى «مكتمل» (أو «مرفوض»).
5. بعد إنهاء الإجراء: «حذف الإيصال» ← يُحذف من Drive إلى المهملات ويبقى سجل الطلب. الحذف يدوي دائماً، لا حذف تلقائي.
6. إن لم يكن Drive مربوطاً أو تعذّر الرفع، يُحفظ الإيصال في Firebase Storage كخطة بديلة (`receiptPath`) ويظهر في اللوحة بنفس الطريقة.

### ربط Drive (مرة واحدة، 5 دقائق)
من `/#admin` ← «ربط Drive»:
1. افتح `script.new` وأنت مسجّل بحساب `atharstudio653@gmail.com`.
2. «نسخ الكود» من اللوحة ← الصقه في المحرر (أو نزّل `Code.gs` من `/apps-script/Code.gs`).
3. غيّر `ADMIN_KEY` أعلى الملف إلى كلمة مرور قوية، واحفظ.
4. نشر ← نشر كتطبيق ويب: «تنفيذ باسم: أنا»، «من يمكنه الوصول: أي شخص» ← انشر ووافق على الأذونات.
5. الصق «عنوان تطبيق الويب» (ينتهي بـ `/exec`) في اللوحة ← «اختبار الاتصال».
6. ضع نفس كلمة المرور في «مفتاح الإدارة» ← «اختبار المفتاح».

المجلد `Athar / Customer Receipts` يُنشأ تلقائياً عند أول إيصال ولا يحتاج مشاركة. مفتاح الإدارة يبقى على جهاز المدير فقط (localStorage) ولا يُحفظ في Firestore؛ يتحقق منه Apps Script في كل طلب (رفع/تنزيل/حذف). عند تغيير `PUBLIC_KEY` أو `ADMIN_KEY` أعد نشر التطبيق (إدارة النشرات ← تعديل ← إصدار جديد).

قيود الجسر: JPG/PNG/WEBP/PDF بحد 10MB، ضغط تلقائي للصور الكبيرة قبل الرفع، و`LockService` لمنع تعارض الكتابة.

### نشر القواعد (إلزامي بعد أي تعديل)
- Firestore: `firebase deploy --only firestore:rules` أو انسخ `firestore.rules` في Console ← Firestore ← Rules ← Publish.
- Storage: فعّل Firebase Storage (قد يتطلب خطة Blaze) وانشر `storage.rules` (تحتوي مسار أيقونات الموقع `site/icons`).
- القواعد القديمة ترفض حقول الإيصال وسجل الموافقات ومجموعة `admins`؛ انشرها قبل التجربة وإلا فشلت الطلبات والدخول.
- تحقق من الآيبان في `src/payment.js` قبل النشر (فحصت صيغته الرقمية فقط، لا ملكيته).

## عبارة العلامة
«لكلِّ منتجٍ حكاية، ولكلِّ حكايةٍ أثر» بخط الرقعة (Aref Ruqaa) في عنوان المتجر، وثلاثة قوالب جاهزة لها في الاستديو (حكاية — فحم / بني / عاج)، يُصدَّر أيٌّ منها PNG مقاس 1080.

## الإيصالات والحماية
- الإيصالات تُحفظ في Drive الأستوديو ويُخزَّن معرّفها (`receiptDriveId`) فقط؛ التنزيل والحذف يمرّان بجسر Apps Script بمفتاح الإدارة.
- إيصالات الخطة البديلة في Storage: يُحفظ المسار (`receiptPath`) ويُولَّد رابط التنزيل عند الطلب لصاحب الطلب أو المدير فقط (قواعد Storage).
- سياسة حذف مقترحة: احذف إيصالات الطلبات المكتملة/المرفوضة بعد مدة تحددها (المدير يملك صلاحية الحذف في Storage).
- قواعد الطلب تتحقق من السعر والعملة ومسار الإيصال. إن غيّرت أسعار `src/bundles.js` فحدّث الخريطة نفسها في `firestore.rules`.
- ضد الإغراق في نموذج التواصل: حقل فخ + مهلة دقيقة في الواجهة، وللحماية الحقيقية فعّل Firebase App Check (reCAPTCHA) من لوحة Firebase.
- تسجيل Google لا يعمل داخل متصفح إنستغرام/سناب/تيك توك: تظهر للعميل رسالة تطلب فتح الرابط في Safari أو Chrome.
